# Log

One file per entry, `YYYY-MM-DD-slug.md`. Chronology is the file listing.

The log records work on the *knowledge structure* — not code tickets (those live in GitHub Projects and PRs). Two things earn an entry:

- an agent session that produced or changed knowledge in `wiki/`
- a meeting: a TL;DR linking the transcript, and any decisions it produced

An entry is the **essence**, not the material: what was decided or leaned, what was left open, files touched, links (issues, PRs, transcripts).

When an entry records a decision that changes what another file in the wiki states, edit that file too and link back to the entry. The log is history; the files it amends carry the current truth.
