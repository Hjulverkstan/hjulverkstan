# Log

One file per entry, `YYYY-MM-DD-slug.md`. Chronology is the file listing.

The log records work on the *knowledge structure* — not code tickets (those live in GitHub Projects and PRs). Two things earn an entry:

- an agent session that produced or changed knowledge in `wiki/`
- a meeting: a TL;DR linking the transcript, and any decisions it produced

An entry is the **essence**, not the material: what was decided or leaned, what was left open, files touched, links (issues, PRs, transcripts, drafts). Proposals and explorations live in `wiki/drafts/`; the entry points at them.

When an entry records a decision that changes a ruling or a product fact, edit the state file too (`conventions/`, `product/`) and link back to the entry. The log is history; the state files carry the current truth.
